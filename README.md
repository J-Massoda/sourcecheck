# SourceCheck

**When two lists disagree, which answer should a team trust?** SourceCheck compares two CSV snapshots, shows conflicts and missing records, and gives a reviewer a place to record a decision. It is for spotting questions, not silently merging data.

For example, a service team sees a customer marked **active** in its CRM and **inactive** in its service register. SourceCheck flags that conflict and shows the original rows. If an email matches but the IDs differ, it suggests a possible match and explicitly leaves identity unconfirmed.

## Run it

Install Node.js 22 or newer. There are no third-party packages or API keys.

```bash
npm run dev
```

Visit the local address printed by the server (normally `http://localhost:5173`). To test and create deployable static files:

```bash
npm test
npm run build
```

## Walkthrough

1. The fictional CRM and service register are preloaded. Inspect the six fields mapped for each source.
2. Run the comparison. Open the **Status conflict** and look at both source rows.
3. Review the **Possible match**. A shared name or email is a clue, never proof of identity.
4. Select a reviewer decision, enter a reason, save, filter the review queue and export the JSON report.
5. Restore the fictional example, or upload two small CSV snapshots and map their columns. CSV needs a header and fields for `id`, `name`, `email`, `status`, `updated_at` (names can differ because mapping is configurable).

The browser reads CSV locally; this demo does **not** upload it to a server or write back to either source. Imported records and review decisions live only in the current page session; refreshing clears them. Do not use personal or confidential records on a publicly shared computer. Limits: 1 MB and 500 rows per CSV. The prototype checks unique IDs, status and email conflicts, repeated IDs, and missing or possible matches. It does not decide source authority, solve many-to-many identities, synchronize databases or automatically correct records. CSV dates are displayed as supplied, not treated as proof of freshness.

## Structure and hosting

`src/model.js` contains the parser, mapping and comparison logic; `src/app.js` contains the local UI and review workflow; `tests/` tests representative CSV and matching cases. `dist/` is generated by `npm run build`. For GitHub Pages, select **Settings → Pages → GitHub Actions**; `.github/workflows/pages.yml` runs tests, builds and publishes on pushes to `main`. Cloudflare Pages can also host it using build command `npm run build` and output `dist`.

A production pilot would need access controls, secure handling and retention of records, documented matching rules, audit history and a designated source owner. This public demonstration does not provide those safeguards.
